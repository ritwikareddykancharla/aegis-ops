§01 · The Problem Statement

Why Production On-Call Triage & Naive AI Agents Fail at 03:00 AM

Why giving an unconstrained LLM raw cloud credentials breaks production—and the exact reliability, safety, and evaluation gaps AegisOps closes for autonomous cloud operations.

🎯 Target Operational Problem Space: Purpose-built around autonomous SEV-1 cloud triage, multi-signal root-cause correlation, zero-trust runbook execution, and trajectory evaluation for AWS DevOps Agent (10608183, 10607465, 10593684) & AWS Infrastructure Eva (10594998, 10541282).

PROBLEM 01 · MULTI-SIGNAL ALERT CHAOS

Multi-Signal Alert Chaos at 03:00 AM

A single bad canary deploy (deploy-v2.14.0-8f92a1), revoked KMS policy, or RDS connection pool leak fires dozens of noisy downstream alarms across CloudWatch Metrics, OpenTelemetry/X-Ray Traces, and container logs. Human SREs burn 25–45 minutes manually correlating suspect_change_id timestamps against W3C trace spans and SOP runbooks while customer checkouts fail.

⚠ Cost of Manual Correlation: 25–45 min MTTR across fragmented telemetry silos
PROBLEM 02 · UNSAFE REACT LOOPS

Unconstrained ReAct Agents Are Unsafe in Prod

Giving an unconstrained LLM prompt loop raw shell or AWS API tools causes skipped diagnostic evidence—jumping straight from a CPU or latency spike to restarting services without checking trace exceptions or recent deployments (PrematureConclusionPolicy: 8.3% DAG compliance)—and catastrophic unapproved mutations (UnsafeMutatingPolicy: attempts dry_run=False in 12/12 outages).

🛑 Unconstrained Failure: Skipped logs + unapproved prod writes (12/12 blocked by AegisOps)
PROBLEM 03 · BLIND FINAL-ANSWER EVALS

Final-Answer Evals Miss Bad Reasoning Paths

Grading only the final Root-Cause Analysis paragraph hides agents that guessed the right root cause by luck while violating runbook prerequisites, hallucinating tool schema parameters, or anchoring on only one symptom during a compound cascading outage (e.g., FAULT-06 where gpt-4o-mini fixed a dropped SQL index but left a 12x zero-backoff retry storm live).

📉 Baseline Blindspot: 75.0% accuracy when deployment correlation is skipped on infra incidents
⚡ How AegisOps Solves All Three in 30 Seconds: (1) Forces every investigation through a checkpointable deterministic state machine over 3 read-only/gated MCP servers so metrics, trace/log signatures, and recent changes are always verified before remediation; (2) Enforces dry_run=True + cryptographic approval_token at the MCP server boundary (blocking 100.0% of unapproved production writes); and (3) Grades both the intermediate tool-call DAG (StepTrajectoryEvaluator: 100.0% compliance) and the synthesized RCA (CalibratedRCAJudge: 95.8% human SRE agreement, κ = 0.9167, 1,000-sample paired bootstrap CI gate).

MODULE 01 · AGENT LOOP & OTEL TRACER aegis_ops/triage_agent.py · otel_tracer.py · web_api.py

Deterministic Incident State Machine & W3C OpenTelemetry Span Tracer

  • State-Machine Control Flow: Enforces strict 7-stage diagnostic progression (ALERT_INGESTED → METRICS_QUERIED → TRACES_CORRELATED → CHANGE_DIFFED → RUNBOOK_MATCHED → DRY_RUN_VALIDATED → HUMAN_APPROVAL_GATE / IncidentTriageAgent) across 12 realistic AWS failure modes (ALB TLS handshake timeout, RDS pool exhaustion, DynamoDB hot partition, IAM KMS key revocation, EKS canary OOM, NAT port exhaustion, Aurora deadlock, AZ grey failure, ASG saturation, CoreDNS throttling, EBS IOPS depletion, Redis eviction storm).

MODULE 02 · TYPED MCP SERVERS & GATE aegis_ops/mcp_servers.py · live_sandbox.py

3 Schema-Validated MCP Tool Servers + Two-Phase Remediation Safety Gate

  • 3 Typed Read-Only / Gated MCP Servers: Implements PrometheusMetricsMCP (metrics_mcp: golden signals & deployment history), CloudWatchLogsMCP (traces_mcp: error log streams & canonical signature clustering), and RunbookRemediationMCP (runbook_mcp: SOP prerequisite lookup & gated execution).

  • Two-Phase Remediation Gate: Permits safe preflight validation (dry_run=True) while cryptographically verifying approval_token on live writes—blocking 12/12 (100.0%) unapproved dry_run=False mutations in UnsafeMutatingPolicy with SAFETY_GATE_VIOLATION.

Directed Acyclic Graph (DAG) Step-Level Trajectory Evaluator & Shadow Differ

PRINCIPLE 01 · CONTROL vs. SYNTHESIS

Constrain Workflow Topology in Code; Delegate Synthesis to the Model

Production DevOps agents should never ask an LLM whether to inspect recent deployments or consult an SOP runbook. Encoding diagnostic prerequisites as a deterministic state machine eliminated Baseline v1's 25% infrastructure blindspot (75.0% → 100.0% accuracy) while keeping foundation-model synthesis where it shines: correlating noisy cross-service evidence.

PRINCIPLE 02 · ZERO-TRUST MCP BOUNDARY

Enforce Blast-Radius Guardrails in the Tool Server, Never the Prompt

Prompt guardrails degrade under long context windows and adversarial log payloads. Moving JSON Schema validation, dry_run=True preflight checks, and cryptographic approval_token verification into RunbookRemediationMCP guarantees a deterministic 0.0% unapproved mutation rate regardless of which model policy is swapped in.

PRINCIPLE 03 · TRAJECTORY CI GATING

Treat Prompt & Model Upgrades Like Production Code Deployments

Pairing deterministic must_precede DAG grading with a length-normalized, position-debiased judge calibrated on 24 Principal SRE postmortems (κ = 0.9167, MAE = 0.0348) turns subjective agent changes into deterministic GitHub Actions pull-request gates (PASS vs. BLOCK_PR).

🔬 Failure Postmortem — Why gpt-4o-mini Failed FAULT-06-CASCADING-RETRY-INDEX (Single-Cause Anchoring Bias):
In FAULT-06, two faults interact: dropping idx_orders_customer_status causes 4ms full-table scans (SCAN orders), which are then amplified 12x to 48.058ms by a concurrent config drift (retry_max_attempts: 2 → 12, retry_backoff_ms: 50 → 0). When inspecting the diagnostic outputs, gpt-4o-mini anchored on the first root cause it saw (SCAN orders in STEP_2_SQLITE_EXPLAIN_PLAN) and chose create_sql_index alone—leaving the 12x zero-backoff retry storm unmitigated in service_config.json. claude-opus-5-5 cross-referenced both STEP_2_SQLITE_EXPLAIN_PLAN and STEP_3_CONFIG_DIFF, executing compound_fix_index_and_retries to restore both the B-tree index and the retry policy (48.058ms → 0.045ms).
